# Reproducing the results

This repository contains two things:

1. **A selectivity-prediction benchmark** — the central, citable result. Four cheap
   computational methods for predicting binding-site selectivity are tested against
   cases where the correct answer is independently known; all four fail. This is the
   subject of the preprint (`docs/paper_A_submission.md`) and is **fully reproducible
   from committed data in minutes**.
2. **A computational tick-target discovery pipeline** — the application context in which
   the benchmark arose. This is larger, hardware-specific, and its early results were
   substantially corrected (see `docs/phase0_findings.md`). It is reproducible but heavier.

**If you only want to reproduce the paper, do Tier 1.** Read `docs/phase0_findings.md`
for the complete, dated record of what was found — including four separate negative
results and the corrections made to the pipeline.

---

## Environment

All code runs in **WSL2 (Ubuntu 24.04)** / Linux. From Windows:
`wsl -u <user> -e bash -c "cd /mnt/c/.../tickdock && python3 ..."`

Command-line tools (see `verify.sh`, `setup_wsl.sh`):

| Tool | Version tested | Used by |
|---|---|---|
| Python | 3.12 | everything |
| BLAST+ (`blastp`, `makeblastdb`) | 2.12.0 | divergence, homolog search |
| AutoDock Vina | 1.2.5 | counter-docking benchmark |
| fpocket | 3.x | pocket detection |
| OpenBabel (`obabel`) | apt | receptor/ligand prep |

Python packages: `biopython`, `rdkit`, `numpy`, `scipy`, `pandas`, `requests`, `matplotlib`.
Install: `pip install --break-system-packages biopython rdkit numpy scipy pandas requests matplotlib`

Some steps fetch from the network (UniProt, RCSB, AlphaFold DB). No GPU is required for Tier 1 or Tier 2.

## Tier 1 — the selectivity benchmark (self-contained, ~minutes)

This is the paper's core result. The DHFR control set is **committed**
(`logs/monomeric_control_set.json`, 5 verified ortholog pairs); the scripts fetch the
handful of PDB structures they need from RCSB at run time.

```bash
# Pocket-restricted identity metric (paper §3.3, Fig 2) — DHFR calibration
python3 scripts/calibrate_monomeric.py            # -> logs/monomeric_calibration.json

# Counter-docking metric (paper §3.4, Fig 3) — the decisive negative result
python3 scripts/calibrate_counterdock.py          # -> logs/counterdock_calibration.json
```

Each script prints the per-pair result table and the PASS/FAIL verdicts (they FAIL — that
is the result). Expected numbers are in `docs/paper_A_submission.md` §3 and in the
committed `logs/*_calibration.json` for comparison.

**Claim → script → output map** (every paper number is traceable):

| Paper claim | Script | Output |
|---|---|---|
| M3 pocket identity, DHFR (Fig 2, §3.3) | `calibrate_monomeric.py` | `logs/monomeric_calibration.json` |
| M4 counter-docking, DHFR (Fig 3, §3.4) | `calibrate_counterdock.py` | `logs/counterdock_calibration.json` |
| Control-set provenance (§2.2) | — (committed) | `logs/monomeric_control_set.json` |

## Tier 2 — the tick non-target divergence (regenerate inputs, ~1 hour)

Reproduces the arthropod acaricide-panel result (paper §3.1, Fig 1) and the
binding-site-transfer / disorder analyses. Large input databases (proteomes, BLAST DBs)
are **not committed** — they are gitignored for size and rebuilt by the fetch step.

```bash
# 1. Download the 13-species non-target proteome panel + build BLAST DBs (~30 min, network)
python3 scripts/fetch_nontarget_proteomes.py

# 2. Whole-protein divergence + the acaricide-panel calibration (paper §3.1, Fig 1)
python3 scripts/nontarget_divergence.py --controls        # -> logs/nontarget_divergence.json

# 3. Pocket-restricted divergence, same calibration (paper §3.2/§3.3)
python3 scripts/pocket_divergence.py --controls-only      # -> logs/pocket_divergence.json

# 4. Binding-site transfer from ligand-bound homologs (paper §13)
python3 scripts/transfer_binding_site.py --controls-only  # -> logs/transferred_sites.json
```

The tick target set itself lives in `data/results/{species}_final_targets.json` (committed).
Structures and docking outputs referenced there are regenerated by the pipeline
(gitignored); the analysis scripts fetch what they need or degrade gracefully.

**Figures:** `out/figures/*.png` were produced from these JSON outputs; the generating
commands are in the git history for the figure commit.

## Tier 3 — the full tick docking campaign (heavy, hardware-specific)

The 139-target × ~10k-compound screen that produced the original dataset. Documented for
completeness; **not required to reproduce the paper**, and its early lead claims were
corrected/withdrawn — see `docs/phase0_findings.md` §11–§14.

- Structure retrieval + pocket detection + docking config: `scripts/03_to_07_structure_to_docking.py`
- CPU campaign orchestrator: `run_campaign.py`
- GPU engine (AMD RDNA-only, Windows-native Vina-GPU 2.1; set `VINA_GPU_DIR`): `scripts/gpu_screen.py`
- Host-homology exclusion (applied post-hoc, §11): `scripts/recompute_host_risk.py`

See `PIPELINE.md` for full campaign commands and `docs/gpu_docking.md` for the GPU build.

## What was corrected (read before trusting any campaign-era number)

The pipeline's early, headline results were found to be artifacts and are documented in
full in `docs/phase0_findings.md`. In brief:

- **All four selectivity-prediction methods fail** a known-answer benchmark (§13–§14). No
  computational selectivity claim in this repo's campaign outputs should be trusted.
- **The PGAP5 (`B7P5E9`) tick-vs-human selectivity ratio (~0.48) is withdrawn** (§14c) — it
  measured pocket-placement difference, not selectivity.
- **66 of 139 targets are excluded** for ≥60% host (human/dog/cat/mouse) identity (§11);
  49% of the raw docking hits were against targets that could not have worked.
- **26 target accessions were deleted from UniProt** (2026_01) and re-anchored (§8).

The one lead that survives every filter is `B7SP41` (a tick legumain) — see
`docs/phase0_findings.md` §10.
